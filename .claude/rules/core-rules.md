# Core rules

Each rule protects the people who use the app (many are children on shared phones) or keeps the
code easy to work in. A rule enforced only "by review" must be checked by hand before handing over.

| #   | Rule                                                                                                                                                                                   | Enforced by                                          |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 1   | The server decides access. A role in the UI only picks which screens to show. The app never sends `organizationId` or any "whose data" ID to choose scope: the server reads the token. | Review                                               |
| 2   | The only roles are `INDIVIDUAL`, `STUDENT`, `TEACHER`, `ORGANIZATION_ADMIN` (`src/auth/roles.ts`), named as in the backend. There is no Super Admin here.                              | `userRoleSchema`                                     |
| 3   | Every page is made with `createPageRoute` and declares `access` and `titleKey`. Every menu item points to a route its role may open.                                                   | `tests/project-rules/routes.test.ts`                 |
| 4   | The access token lives in memory only. The refresh token is an httpOnly cookie the app never reads. No token or personal data in browser storage.                                      | ESLint storage ban + `src/utils/storage.ts` key list |
| 5   | Browser storage only through `src/utils/storage.ts`, and only its listed keys (theme, language, the signed-out flag).                                                                  | ESLint + `eslint-rules.test.ts`                      |
| 6   | Only `src/api` calls `fetch`. Every response is checked with a Zod schema before it is used.                                                                                           | ESLint + the `api` client's signature                |
| 7   | No `dangerouslySetInnerHTML`, `eval` or `new Function`. Text from AI or markdown renders without raw HTML. Redirects go through `getSafeRedirectPath`.                                 | ESLint + `safe-redirect.test.ts`                     |
| 8   | No inline script and nothing loaded from another site: no CDN, third-party font, analytics or tracker.                                                                                 | `tests/project-rules/security-headers.test.ts`       |
| 9   | Env is read only in `src/config/env.ts` and checked with Zod at start. `VITE_*` values are public: never a secret. Claude never reads or edits `.env`.                                 | ESLint + `.claude/hooks/protect-env.mjs`             |
| 10  | The service worker stores only the app's own static files. Nothing from `/api` is cached, and `/api` never gets the app shell.                                                         | `tests/project-rules/pwa.test.ts`                    |
| 11  | A join code only creates a pending request. No Organization screen shows until the server says the request is approved.                                                                | Review                                               |
| 12  | Color values live only in `src/styles/tokens.css`. Every text and border pair meets WCAG AA in every theme and mode.                                                                   | `colors.test.ts`, `contrast.test.ts`                 |
| 13  | Red is for real errors (and the required star). Amber is for "Needs practice" only. Color never carries meaning alone: add an icon and a word.                                         | Review                                               |
| 14  | All screen text lives in `src/lang/en.json`. No text typed into JSX.                                                                                                                   | ESLint `no-literal-string` + `lang-keys.test.ts`     |
| 15  | Modules build screens from `@/components` only: no raw `<button>`, `<input>`, `<select>`, `<textarea>`.                                                                                | ESLint + `eslint-rules.test.ts`                      |
| 16  | Code outside a module imports it only through its `index.ts`. Shared code never imports a module or `src/app`.                                                                         | ESLint `no-restricted-imports`                       |
| 17  | "Organization" is always written in full, in code, file names and text. Files and folders are kebab-case.                                                                              | `tests/project-rules/naming.test.ts`                 |
| 18  | Every test lives under `tests/`. Nothing next to the source file.                                                                                                                      | Review                                               |
| 19  | Keep it simple: no new file, layer, helper or package unless the task needs it now. A package needs a reason in the commit message.                                                    | Review                                               |
| 20  | No `any`, no floating promises, no `console.log`, no default exports in `src/`.                                                                                                        | ESLint                                               |
| 21  | A change is done only when `pnpm check` passes.                                                                                                                                        | Definition of done in `CLAUDE.md`                    |
