# Core rules

Each rule protects the people who use Buddy (many of them minors) or keeps the code easy to work in.
Code comments, ESLint messages and test names refer to them as "core-rules #N". A rule enforced
only "by review" must be checked by hand before handing over a change.

| #   | Rule                                                                                                                                                                                              | Enforced by                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1   | Colors come only from the tokens in `src/styles/tokens.css`. No color value (hex, rgb, hsl, oklch) and no Tailwind palette class (`bg-indigo-600`, `bg-white`) anywhere else.                     | Palette reset in `index.css` + `tests/guardrails/colors.test.ts`           |
| 2   | Each color has one meaning: `primary` = actions, `progress` (green) = progress and strong topics, `weak` (amber) = weak topics only, `destructive` (red) = real errors only. Never color alone.   | Review (`design-system.md`)                                                |
| 3   | Every theme × light/dark passes WCAG AA: 4.5:1 for text, 3:1 for borders, icons and focus rings.                                                                                                  | `tests/guardrails/contrast.test.ts`                                        |
| 4   | Screens are built only from `src/components`. A feature never uses a raw `<button>`, `<input>`, `<select>` or `<textarea>`. A new look is a new variant of the component, not a one-off override. | ESLint `no-restricted-syntax` + review                                     |
| 5   | All screen text lives in `src/lang/en.json` and is read with `useLang()` or `getLang()`. No text typed into JSX. Every language file has the same keys and placeholders as English.               | ESLint `i18next/no-literal-string` + `tests/guardrails/lang-keys.test.ts`  |
| 6   | Every route declares its `access`. Every nav item points to a route its role may open.                                                                                                            | `defineRoute` + `tests/guardrails/routes.test.ts`                          |
| 7   | The app never decides security. Role checks only hide things; the server enforces. The app never sends `organizationId` (or any "whose data" ID) to choose whose data it gets.                    | Review + `add-api-hook` skill                                              |
| 8   | The access token lives in memory only; the refresh token only in its httpOnly cookie. Browser storage never holds tokens or personal data, and is used only through `src/lib/storage.ts`.         | ESLint `no-restricted-globals` + review                                    |
| 9   | Only `src/lib/api/` calls `fetch`. Only a feature's `api/` folder calls the API client. Every response is checked with a Zod schema before use.                                                   | ESLint + review                                                            |
| 10  | A feature is imported only through its `index.ts`. Shared code (`components`, `lib`, `hooks`, `theme`, `lang`, `config`, `pwa`) never imports a feature or `app/`.                                | ESLint `buddy/import-boundaries` + `tests/guardrails/eslint-rules.test.ts` |
| 11  | No `dangerouslySetInnerHTML`, `eval` or `new Function`. Links built from data go through `safeUrl()`, redirects through `safeRedirect()`. AI and markdown output render without raw HTML.         | ESLint + review                                                            |
| 12  | `import.meta.env` is read only in `src/config/env.ts`, which checks every value with Zod. `VITE_*` values are public: never a secret.                                                             | ESLint + `tests/guardrails/env-files.test.ts`                              |
| 13  | The service worker caches only the app's own static files, never `/api`. Logout clears the query cache.                                                                                           | `vite.config.ts` + tests                                                   |
| 14  | Every screen works from a 320px phone to a laptop, in light and dark, with touch targets of at least 44px and a visible keyboard focus.                                                           | Playwright + axe + review                                                  |
| 15  | Every screen that shows data has loading, empty, error and offline states.                                                                                                                        | `add-page` skill + review                                                  |
| 16  | "Organization" is written in full in code, file names and text: `organizationId`, never `orgId`.                                                                                                  | `tests/guardrails/naming.test.ts`                                          |
| 17  | Heavy AI work never blocks a screen: start a job, show progress, then poll or stream (with `fetch`). The browser never calls a model provider.                                                    | `ai-features.md` + review                                                  |
| 18  | No third-party scripts, fonts, trackers, analytics or ad SDKs. Fonts and icons are self-hosted.                                                                                                   | CSP + review                                                               |
| 19  | No `any`, no floating promises, no `console.log` (use `logger`), named exports only in `src/`.                                                                                                    | ESLint                                                                     |
| 20  | No new package unless the browser, React or the current packages can't do the job. The reason goes in the commit message.                                                                         | Review (`pnpm add` asks first)                                             |
| 21  | A change is done only when `pnpm check` passes (lint, typecheck, test), plus `pnpm e2e` when screens changed.                                                                                     | Definition of done in `CLAUDE.md`                                          |

Some files these rules name arrive in later setup steps (see "Setup status" in `CLAUDE.md`). Until
a guardrail exists, its rule is enforced by review.
